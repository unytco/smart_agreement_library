## [Unreleased]

### Added

- `holo_hosting_proof_of_service`: a customer-maintained host ALLOW-list (default-deny — an execution pays only the hosts its effective list names). The standing list is seeded by a new required Fixed input `initial_allow_list` (`[]` when hosters are unknown at creation), updated by consumable `ParkedData` parks from a new `list_publisher` role whose payload carries `allow_list_deltas: {add, remove}` (all adds apply before all removes — deterministic regardless of park order), and carried forward in each RAVE's `carryover.allow_list` alongside the locked funds. **Scope of enforcement:** this run's deltas are chain-enforced — role qualification on parked links stops an unqualified agent creating one (so qualify `list_publisher` to the customer at instantiation), and consumed-input binding ties each delta's value to the link it names, so the executor can neither forge nor rewrite one. The *carried* list is not: it arrives via `previous_execution`, a `Custom` input, and validation re-derives `locked` from the real predecessor (Rule 7) with no equivalent for `carryover`, so a dishonest executor can present a carried list the customer never authored — provable after the fact from their signed parks, but not prevented. Closing it needs DNA-side re-derivation of `carryover`; re-stating the full list as a fresh delta each period keeps the enforced portion current, and a customer needing outright enforcement must execute the agreement themselves. Delta entries are shape-checked in the script rather than the input schema, because a schema violation fails Rule 2 before the script runs and one malformed park would deadlock every settlement. Delta parks are author-gated in the script via `get_spend_links_author` (the link author is validator-derived), so a host cannot allow itself under an honest executor even before the DNA-level role-qualification enforcement the unyt devs are adding; gating and defensive payload reads run before any content is touched, so a malformed or hostile park can never deadlock settlement (consumable parks are only deleted by a successful execution). A host off the list is never paid and never counts toward the shortfall figure, while its metered work stays in the metering credit (the harvester parked those service units without knowing the list, and conservation requires every consumed parked unit to land in an allocation); consumed delta parks carry no funds and are not named — allocation sources may only be parked spends or the prior RAVE. A settlement that would consume an invoice for a host the list does not name throws pre-commit instead (a successful run would delete those parks and Rule 5 bars re-consumption, destroying the work unpaid), covering every route to that state: an unseeded list, a mid-period removal of a host that already parked work, and a mistyped seeding key. The new optional `discard_unpayable` executor input settles anyway when dropping that work is deliberate. The guard sits below the `unlock` branch, so reclaiming funding stays available even while unpayable invoices are parked — the only recovery from a wrong `funds_owner_pubkey`. `initial_allow_list` entries are schema-validated as agent pubkeys (`uniqueItems`), matching `funds_owner_pubkey`.
- `holo_hosting_proof_of_service`: a new required Fixed input `funds_owner_pubkey` (the customer's key) — the agent paid by `unlock` and by the per-dimension metering credit, and the only author whose allow-list deltas count. Nothing cross-checks it against the role authorizations (the script cannot see roles): a wrong-but-valid key at instantiation redirects unlock/metering and causes every real customer delta to be ignored — the sample's role comments carry the requirement, instantiation tooling should qualify the customer-side roles to the same key, and the parent app's sweettest pins the misconfiguration semantics. The canonical instance authorizes the Log Harvester as sole executor (carry-forward locking requires one), so Holo settles on its own cadence while the customer keeps exclusive control of funding and the allow-list through their parks; `unlock` pays the customer, not the executor.

### Changed

- `holo_hosting_proof_of_service`: the sample agreement carries its role qualifications and executor as DATA — each role `Authorized` to a placeholder agent key, and `AuthorizedExecutor` likewise — instead of `Any` plus a comment saying what to set. The placeholder is a structurally valid key (an all-zero core with its real DHT-location checksum, `uhCAkAAA…CZ9h_C`) because `AgentPubKeyB64` validates that checksum, so a `<Placeholder: …>` string cannot deserialize and would fail template load. Qualifying `list_publisher` is what makes the DNA refuse a stranger's allow-list park outright; the script's author gate now documents itself as the secondary control, covering only the case where the qualification and `funds_owner_pubkey` disagree or a role was left as `Any`.
- `holo_hosting_proof_of_service`: `runtime_input_signature.json` documents the `allow_list_deltas` shape (`{add, remove}` of agent pubkeys) with descriptions rather than types. It stays deliberately unconstrained: a schema violation fails validation before the script runs, and one malformed park would then deadlock every settlement, since a consumable park is only deleted by a successful execution.
- `holo_hosting_proof_of_service`: align the metered dimensions with the unit registry a Holo Hosting network actually builds. Unit indices are positions in the global unit registry, and the canonical setup registers HF, HOT, BW (bandwidth), ST (storage), then the WindTunnel units — so the table's `2` is BW and `3` is ST, where it previously assumed `2` storage and `3` gossip, with the WindTunnel placeholders one index too high. Bandwidth is now metered as the gossip count (`g`, `base_per_gsp`) on `2`, storage as `s`/`base_per_st` on `3`, and WindTunnel on `4`/`5`. The `gets` dimension is dropped: no unit backs it today (it is reserved for holo-web-conductor). A mismatch here settles and pays correctly while crediting the wrong unit, so it is silent — the header now says the registry, not the assumption, is authoritative.
- `holo_hosting_proof_of_service`: the insufficient-funding error keeps its leading phrase but now reports the actionable shortfall (outstanding − available funding including any carried lock) as the payment figure, with the outstanding total and available funding in parentheses — all accumulated in exact fuel strings (`add_fuel`/`sub_fuel`), never f64, so the printed top-up is never a micro-unit short.
- `holo_hosting_proof_of_service`: the metering credit (per-dimension service-unit totals) now goes to `funds_owner_pubkey` — the customer — rather than the executor, and names every consumed invoice and delta park even when nothing was metered (a name-only allocation), so such runs settle instead of leaving consumed parks unnamed.

### Fixed

- `__system_transaction_fee_collection`: one allocation to the collector, its amounts summed per unit across every parked spend it sweeps and its `sources` naming all of them. It returns no `computed_values`.
- `ioen_rec`: emit `amounts` as a unit map (`#{ "0": total }`), not an array — the array shape does not deserialize into `UnitMap` and contradicted the template's own `output_signature.json`. Its example agreement now uses the real `AuthorizedExecutor` variant and an array-valued `Authorized` qualification.
- Docs: the output contract had allocations as `amount` arrays and `credit_limit` as an `{ agent, amount }` object; both are unit maps. Executor rules are `AuthorizedExecutor` with one key, not `AuthorizedExecutors` with a list.
- Docs: dead links — `docs/rave_rules.md` and `unytco/unyt-releases` in `README.md`, the `RAVEOutput` docs.rs path in `CONTRIBUTING.md`.
- `__system_credit_limit_computation_holo_hosting`: declare `special_agent` and `special_credit_limit` in `runtime_input_signature.json` — the script reads both, but the signature was a copy of the generic template's, which has neither.

### Changed

- Docs: documented the previously undocumented — the `#{ "output": … }` return shape with `rejected_links` / `redacted_links`, the `locked` and `carryover` outputs, `other_options.json`, which template files are required, and the `spender` role-naming rule (folded in from `docs/rough_rules.md`, now removed).

### Added

- `lockbox`: a minimal AuthorizedExecutor agreement that holds conserved base-unit funds — parks and locks the remainder, carries the lock forward, spends it down, and unlocks it back to the creator. The proving ground for the locked-funds primitive.

### Changed

- `lockbox` + `holo_hosting_proof_of_service`: a hold names its funding with a name-only (empty `amounts`) allocation, so it settles and collects instead of stranding an uncollectable deposit; the holo-hosting no-metered-work lock now settles too.
- `holo_hosting_proof_of_service`: a host invoice draws from as many customer allocations as needed (split funding settles); a zero-priced invoice emits no payment.
- `holo_hosting_proof_of_service` + `lockbox`: numeric reads go through the engine's `to_num` — accepts a number or numeric string, refuses garbage loudly instead of silently pricing at 0.
- These three changes need an engine carrying `to_num` + `consume_allocations` (rave_engine > 0.6.0).
- `holo_hosting_proof_of_service`: lock the unspent base-unit funding instead of returning it to the executor, auto-apply the carried lock on the next run (spend-down), and add an `unlock` executor input to reclaim it; `input_rules` gain `previous_execution` and `unlock` (both declared in the runtime input signature).
- `holo_hosting_proof_of_service`: the EdgeNode Customer (executor) role's `comment` now notes it must be the sole `AuthorizedExecutor`, not `Any` — the agreement locks funds, which the DNA rejects under `ExecutorRules::Any` (the `lockbox` Locker role already documents this in its description).
- `holo_hosting_proof_of_service`: pay EdgeNode Hosts for both Holo services through one agreement instance.
- `holo_hosting_proof_of_service`: price five optional dimensions (storage, gossip, gets, 2 WindTunnel); absent ⇒ 0.
- `holo_hosting_proof_of_service`: fix the gossip/storage unit-index swap so each dimension credits its own index.
- `holo_hosting_proof_of_service`: rename the paying role Happ Provider → EdgeNode Customer.
- `__system_credit_limit_computation_holo_hosting`: narrow the special agent's elevated `special_credit_limit` to the HoloFuel unit only (index `0`), dropping the stale, over-broad second index, and set it to `177619433541.14`.
